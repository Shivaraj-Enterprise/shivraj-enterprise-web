# Project Architecture Rules
- Monthly reports aggregate contact enquiries, job applications, and source-labelled leads using Indian calendar-month boundaries; keep exports paginated and spreadsheet-safe, and CV links signed so owner reports are complete without exposing private files.

- Keep calculator motion and elevation styles scoped under `.calculator-page` so they cannot affect other pages; this preserves the site's existing visual behavior.
- Use the `@react-bits` shadcn registry for React Bits components; `.agents/mcp_config.json` configures its local shadcn MCP client without changing the website's own MCP server.
- Keep Kokonut UI registry components compatible with Tailwind v3 and the existing Framer Motion package; homepage activity rings visualize established company milestones while their text values remain static for search engines.
- Use the `@magicui` shadcn registry for Magic UI components; `.agents/mcp_config.json` also configures the local `@magicuidesign/mcp` client without changing the website's own MCP server.- Shared Motion wrappers live in `src/components/motion/` and respect reduced motion; reuse them instead of per-page animation code so effects stay consistent.
- Article pages own their reading-progress bar instead of stacking it with the global bar; shared heading reveals keep headings visible before animation for indexing and accessibility.
- Adapt OriginKit motion to the existing Tailwind v3 stack with semantic tokens; expose it through shared motion exports and scope homepage effects under `.homepage-motion` to preserve other pages and static company figures.
- Weekly blog topics come only from a fresh last-7-days news search each run (no fixed topic lists), with every candidate logged in `blog_topic_history` and a weekly lock in `blog_generator_state`, so topics stay current and never repeat.
- Weekly article and Monday FAQ research share `_shared/news-research.ts`: gateway-backed Firecrawl news/content (at most four searches per run), free Google News fallback, dated publisher evidence, and research-only checks without writes; this bounds cost and prevents invented or stale news.
- Scheduled editorial AI calls use the pinned `@lovable.dev/ai-gateway` SDK through `_shared/editorial-ai.ts`, retaining the existing model and generated declarations; this keeps contracts and safe transport retries consistent.
- Clear a weekly AI pause only after successful article publication and check the state update result; this restores cron after manual recovery without blindly retrying credit or permission failures.
- When code needs `window.open`'s return value (pop-up-block detection, analytics on success), never pass `noopener` in the features string — it forces a null return even on success; detach the opener manually instead.
- Weekly articles are shared to LinkedIn by the `publish-linkedin` function (called after publication, logged in `social_posts`, one post per article); a LinkedIn failure never blocks article publication.

- LinkedIn posting claims a `publishing` social_posts row before calling LinkedIn; a partial unique index allows one publishing/published row per article, so retries and parallel runs cannot double-post.
- Google Business updates use a dedicated admin-only function and unique location/update claims; weekly publishing requires an explicit opt-in, and unknown provider outcomes stay locked to prevent duplicate public posts.
- Search Console buyer queries may inform weekly discovery only when backed by fresh seven-day news; monitoring failures never block the weekly article.
- Enquiry links carry service, area or calculator assumptions into the existing stored contact form and WhatsApp; shared industrial-area content refines existing pages rather than creating duplicate city doorway pages.
- Quote and company-profile alerts use a shared sender with event-derived idempotency keys (Resend first, business Gmail fallback); customer auto-replies go from the business Gmail at most once per address per day to prevent abuse; save leads before notifying and distinguish provider acceptance from delivery so failures never cause lost leads or false delivery claims.
- Candidate sourcing reuses private job applications and short-lived CV links; recruitment sharing contains only public job information and requires an explicit owner action to avoid exposing applicant data or broadcasting automatically.
- Monday growth engine (`monday-growth-engine`) snapshots weekly Google and Bing data plus up to 3 Semrush keyword calls (free-plan quota) into `growth_reports`, emails the owner, and writes 3 search-driven FAQs into `weekly_trending_content` (read by the homepage) and resubmits the sitemap plus last week's articles to Bing; it never edits code or business facts (rates, contacts), so live changes stay safe.
- Monday local demand research uses one cached, batched Perplexity Search request with Google News fallback; only dated seven-day local industry evidence enters FAQs and the stored owner briefing, so speculative expansion/tender signals never become confirmed leads or automatic outreach.
